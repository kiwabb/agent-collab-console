# Logging Guidelines

> How logging is done in the MetaGPT package.

---

## Status: Not in active use (as of 2026-06-03)

The MetaGPT package spec is **scaffolded by `trellis init`** but
**no current code in this repository is filed under MetaGPT** and
no active task uses `"package": "MetaGPT"` (the only package
labels in the trellis task history are `ccgui` and `vibe-kanban`).

The placeholder files were generated by the bootstrap task and are
preserved so that the spec index stays consistent. The day a task
first lands with `package: MetaGPT`, this file gets replaced with
real content grounded in that code.

## Where the real conventions live

- **Backend conventions for the actual backend in this repo** live
  in `.trellis/spec/vibe-kanban/backend/`. That is the spec
  sub-agents should read today.
- **Frontend conventions** live in `.trellis/spec/ccgui/frontend/`.
- Gotchas and stack notes for the actual product are in
  `CLAUDE.md` at the repo root.

## When to fill this file

A new spec file here is required when **all** of the following are
true:

1. A task with `"package": "MetaGPT"` exists in
   `.trellis/tasks/` (active or recently archived).
2. There is real code in the repository that the package label
   covers.
3. The conventions in that code area differ from `vibe-kanban`
   enough to warrant a separate spec (different framework,
   different store, different concurrency model).

Until then, treat this file as a marker, not a contract.
