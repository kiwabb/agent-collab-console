## 逐阶段实现

### Phase 0 — 超时配置单一真相源
- 新建 `backend/app/application/timeouts.py`：集中 9 个超时常量 + `lease_pulse_interval_s()` 派生 + `check_invariants()/validate()` 启动断言（如 `LEASE_TTL < SUBAGENT_IDLE`、`CODEX_IDLE <= CODEX_TURN`）。env 名/默认值完全不变 —— 纯重构。
- 调用点改为集中 getter：`conductor_lease.py`、`conductor_tools.py`、`codex_app_server_runtime.py`、`stall_watchdog.py`、`conductor_main_loop.py`。
- `main.py` lifespan 启动时 `timeouts.validate(strict=False)` —— 坏 env 组合在 boot 大声报错而非静默踩坑。
- 测试：`tests/test_timeouts.py`（9 例）。

### Phase 1 — Conductor 生命周期可靠性
- **GAP A（心跳容错）**：抽出可测的模块级 `_run_heartbeat_pulse()`，瞬时续租失败只 log+计数、**不杀**脉冲循环；连续 3 次失败发 `conductor_heartbeat_degraded` 事件。`persist_turn` 内的心跳调用也改为非致命。
- **GAP B（relaunch 熔断）**：`conductor_recovery._try_relaunch` 加熔断 —— 用"本 issue 的 orphan-stalled 任务数"作无状态计数器，超过 `CONDUCTOR_MAX_RELAUNCHES`（默认 3）则停止 relaunch、seal issue 为 `failed`、发 `conductor_relaunch_exhausted`。杜绝 launch→crash→relaunch 死循环。
- **GAP C（非法转移强制收尾）**：`transition_conductor_phase` 对"从终态（done/failed/stalled）复活到活跃相位"的非法转移直接**阻断**（保持终态）并发 `conductor_state_violation{blocked:true}`；其余非法转移保留历史 warn-and-apply。
- **GAP D**：经核实 `codex_app_server_runtime._on_raw_line` 已在每条 raw line 重置 idle 时钟（注释明确"only true stdout silence trips"）—— **活动感知已存在**，叠加 P0 的 `codex_idle <= codex_turn` 不变量即足够。不做冗余改动（避免回归）。
- 测试：`tests/test_conductor_recovery.py`（熔断跳闸/计数）、`tests/test_conductor_state_machine.py`（阻断 vs 告警分类）、`tests/test_conductor_main_loop.py`（脉冲失败不致命 + 取消传播）。

### Phase 2 — 执行器结果闭环（最大功能缺口）
- **GAP E（核心）**：`api._refresh_task_result` 在 `persist_result` 抛错（schema 不匹配）时给 task 挂 `_validation_error` 标记；`workflow_scheduler.on_task_completed` 检测到标记则用 `status=artifact_invalid`（而非误导性 `done`）signal Conductor，并发 `artifact_validation_failed` 事件。Conductor system prompt 增补：收到 `artifact_invalid` 须带"期望 schema + 哪里错"重派，不得当成功推进。
- **GAP F（nudge 结果落盘）**：stall watchdog 的 chat-nudge 跑完后 `_recover_nudge_result` 把 task 提升 done 并跑 `refresh_task_result` 抽取+持久化（经 GAP E 校验）；无可用结果则恢复 failed —— 最坏与原行为一致。
- **GAP G（重派上限）**：`dispatch_subagent` 按图中同 role 节点数 cap（`CONDUCTOR_MAX_DISPATCHES_PER_ROLE` 默认 4），超限返回 `retries_exhausted`，prompt 告知 LLM 停止重派该 role。
- **GAP H（全角色 fallback）—— 经分析的范围决策**：engineer fallback 之所以有价值，是因为它从磁盘 git state 恢复**真实工作**；QA/architect/PM 只产出 LLM 报告本身，停滞时无可恢复内容，合成空占位产物比现有"failed→Conductor 重派"（已被 GAP E 强化）更糟且更脆弱。故**不**为非 engineer 角色加占位合成（架构正确性优先）。
- 测试：`tests/test_artifact_validation_signal.py`（GAP E 信号 + GAP G cap）、`tests/test_stall_watchdog_recovery.py`（GAP F 恢复/保持 failed）。

### Phase 3 — 可观测性结构化事件
- **GAP I**：stall watchdog 发 `stall_detected`（task/issue/role/executor/silence_s）、`stall_recovered`、`stall_nudge_failed`，可按 role/executor 计数而非 grep。
- **GAP J**：`artifact_validation_failed`（P2 产出）经 EventBus 自动套标准 `{v,ts,event_id,type,payload}` 信封，带 issue_id scope。
- **GAP K**：codex app-server 启动崩溃（坏 model id / 缺二进制 / dyld 崩）以前会让 `initialize()` 永久挂起、烧满 turn budget。新增 `_initialize_or_fail_fast` 把握手 race against 进程退出 + `CODEX_HANDSHAKE_TIMEOUT_S`（默认 30s）硬上限，早退时抓 stderr 发 `executor_failed_to_start` 并快速失败。
- 测试：`tests/test_observability_events.py`（stall 事件 + 握手 fail-fast/happy path）。

### Phase 4 — 产品 UX 呈现
- 新增 `useConductorAlerts(issueId)` hook + `ConductorAlerts` 横幅组件：消费 P1-P3 的全部新事件，按 severity（danger/warn/info）渲染可忽略告警；`stall_recovered` 解除对应 `stall_detected`。
- 挂载于 `IssueDetailPage` StatusStrip 下方（镜像 `LatestFailureAlert` 模式）。熔断放弃时 issue 已 seal 为 `failed`，徽章显示"失败"+ 告警横幅说明原因（比新增 status 枚举更干净）。
- `BusEventType` union 补全 7 个新事件类型；i18n key（中/英）齐全。
- 测试：`tests/conductorAlerts.test.ts`（severity 映射 + describeAlert 参数化，3 例）。
